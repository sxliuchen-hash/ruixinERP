## 3. 提交纳入范围

生产候选提交应纳入：

1. `backend/src/`、`backend/scripts/`、`backend/tests/` 中统一权限、SSO、数据范围、企微、数据库迁移、备份恢复和发布门禁代码。
2. `frontend/src/`、Vite 配置、前端依赖锁和安全环境模板。
3. `.github/workflows/ci.yml`、根/前后端 `.gitignore`、可提交的 `.env*.example`。
4. `deploy/nginx.conf`、PM2 配置和正式运维文档。
5. Manifest、接口/按钮权限矩阵、R7 回填、证据矩阵和风险例外文档。
6. 删除曾受 Git 管理的真实 `.env.production`，以 `.env.production.example` 取代；历史中出现过的真实 Secret 仍必须轮换。

## 4. 明确排除范围

不得加入生产候选提交：

- `tmp/`、DOCX 渲染 PNG/PDF、测试过程日志和临时构建脚本。
- `frontend/dist/`、`node_modules/`、`.npm-cache/`。
- 真实 `.env`、`.env.production`、`.env.test`。
- 私钥、公钥临时副本、Secret、密码、Token、Code、assertion、账号密码。
- 数据库备份、`.sql.gz`、SHA sidecar、receipt、COS 下载工件。
- 服务器 SSH 私钥、公钥部署文件或 known_hosts 临时文件。
- 本机 IDE、缓存、日志和操作系统文件。

## 5. 推荐的提交方式

由于本轮改造跨越前后端、数据库、部署和文档，且完整测试证明的是整体工作树，推荐冻结为一个经过审计的 RC 集成提交，不在发布前临时拆分成无法独立通过测试的小提交。

建议流程：

1. 根据第 3、4 节完成最终文件清单审查。
2. 执行敏感值扫描和环境模板门禁。
3. 暂存候选文件后复核 staged diff，确认没有 `tmp/`、真实环境文件或凭证。
4. 在暂存内容不再变化后运行完整门禁。
5. 经项目负责人明确授权后创建生产候选 Commit。
6. 推送候选分支并等待精确 Commit 的 CI 通过。
7. CI 通过后创建 annotated Tag，建议：`erp-unified-auth-r7-rc1`。
8. 将 Commit、Tag、CI 链接和生成时间回填 M-09。

未经明确授权，本清单不执行 `git add`、`git commit`、`git tag` 或 `git push`。

## 7. Commit 后、服务器部署前必须补齐

1. 恢复 ERP 服务器 SSH 公钥登录，并由运维确认目标主机、账号和最小权限。
2. 确定首个测试主账号 `users.id`；建议使用管理员账号，但必须确认已启用、已绑定 ERP，并可完成 Employee 建档。
3. 安全交付四套 Secret、`ERP_SESSION_SECRET`、active `kid` 和 active 公钥；不在本文记录明文。
4. 配置认证开关、Redis、回调、四套凭证和 active key，使 production preflight 通过。
5. 创建/授权 business Client，完成 M-06、M-16～M-18。
6. 部署后完成 Manifest 同步和审计，完成 M-12、M-13。
7. 准备七类账号及操作人，完成 M-08、M-19 和七场景验收。
