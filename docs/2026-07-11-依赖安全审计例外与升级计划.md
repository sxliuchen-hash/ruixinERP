# ERP 依赖安全审计例外与升级计划

更新时间：2026-07-11

## 1. 当前结论

- 前端生产依赖和完整依赖审计均为 0 漏洞。构建工具已升级到 `vite@6.4.3`，实际使用 `esbuild@0.25.12`。
- 后端仍有 3 个 production moderate，均来自 `exceljs@4.4.0`、`sequelize@6.37.8` 共同依赖的 `uuid@8.3.2`。
- 后端当前没有 high 或 critical 漏洞，但不能表述为“0 漏洞”。

## 2. 后端临时风险例外

| 项目 | 内容 |
| --- | --- |
| Advisory | `GHSA-w5hq-g745-h8pq` |
| 受影响范围 | `uuid < 11.1.1` 在调用 v3/v5/v6 且传入 `buf` 时缺少 buffer 边界检查 |
| 当前锁定版本 | `uuid@8.3.2` |
| 引入链路 | `exceljs@4.4.0 -> uuid@8.3.2`；`sequelize@6.37.8 -> uuid@8.3.2` |
| 当前实际调用 | ExcelJS 仅调用 `uuid.v4()`；Sequelize 仅调用 `uuid.v1()`/`uuid.v4()`；ERP 业务代码未直接调用 uuid |
| 可达性判断 | 未发现公告要求的 v3/v5/v6 + `buf` 调用，当前漏洞路径不可达 |
| npm 修复状态 | `fixAvailable=false` |
| 风险决定 | 有期限接受 moderate 风险；不得把该结果写成 0 漏洞 |
| 复核期限 | 每次 ExcelJS/Sequelize 升级及每个生产候选版本重新执行 `npm audit --omit=dev` |

本例外不允许恢复或新增以下调用：

- `uuid.v3(..., buf, ...)`
- `uuid.v5(..., buf, ...)`
- `uuid.v6(..., buf, ...)`
- 任何绕过 lockfile 的 uuid 版本降级

## 3. 后续升级验证

上游依赖放宽 uuid 主版本约束后，优先采用上游正式版本。若需提前验证 `uuid@11.1.1` override，必须在独立分支完成以下门禁后再决定是否上线：

1. 后端全量 Jest 和开放句柄检查。
2. MySQL 8.4 数据库集成测试、事务和迁移测试。
3. Excel 导入、Excel 导出及带条件格式的工作簿生成回归。
4. Sequelize 事务 ID、查询日志 ID 和工资/财务主流程回归。
5. `npm audit --omit=dev`、后端 lint、模块加载和生产构建相关门禁。

跨越依赖声明主版本的 override 未完成上述验证前，不得直接进入生产。
