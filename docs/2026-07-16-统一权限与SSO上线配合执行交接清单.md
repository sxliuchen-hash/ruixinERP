# 主项目统一权限与 ERP SSO 上线配合执行交接清单

> 本文已被主项目正式反馈修订，不再作为当前执行依据。当前执行版本为
> `docs/2026-07-16-ERP对主项目交付反馈确认与修订执行清单.md`。

## 1. 文档用途

本文用于明确三类工作：

1. 主项目团队需要向 ERP 团队交付什么；
2. 哪些操作必须由主项目团队在主项目服务器上执行；
3. 哪些操作由 ERP/运维团队在 ERP 服务器或独立发布环境执行。

本文是 2026-07-16 的当前执行清单。既有 R7 文档继续作为技术契约和设计依据，但其中关于候选提交、SSH 和部署准备状态的历史描述不再作为当前状态。

## 2. 操作边界

- ERP 团队及本次协助人员不得直接修改主项目服务器端内容。
- 主项目目录、主项目数据库、主项目 PM2、主项目 Nginx、主项目环境变量和主项目密钥，只能由主项目团队操作。
- ERP 服务器操作范围仅限 ERP 路径、ERP 数据库、ERP PM2 和 ERP 站点配置。
- 两套系统部署在同一台服务器时，任何 ERP 操作都不得重启 `patent-backend`，不得改动 `/www/wwwroot/patent-notice-system`。
- Secret、密码、私钥、完整 assertion、Token 和一次性 Code 不得写入本文、工单正文或普通聊天。

路径边界：

| 系统 | 路径/进程 | 操作责任方 |
| --- | --- | --- |
| 主项目 | `/www/wwwroot/patent-notice-system`、`patent-backend` | 仅主项目团队 |
| ERP 后端仓库 | `/var/www/erp`、`erp-backend` | ERP/运维团队 |
| ERP 前端站点 | `/www/wwwroot/erp.iptt.top` | ERP/运维团队 |
| ERP 候选 | `/var/www/erp-releases/erp-unified-auth-r7-rc1` | ERP/运维团队 |

## 4. 主项目团队需要交付给 ERP 的内容

### 4.1 主项目 R7 部署回执

主项目团队完成部署后应回传：

- 实际部署的完整 Commit；
- Tag；
- 部署时间；
- `patent-backend` 启动时间或进程回执；
- 健康检查结果；
- 数据库迁移 pending=0 的只读复核结果；
- 回滚版本和回滚负责人。

目标必须为：

```text
Tag: release/20260715.2
Commit: 4eb34205306bb204a9af3e3b905d6b33493b4773
```

### 4.2 四套独立 Client 凭证

| Client ID | 调用方向 | 用途 | 配置要求 |
| --- | --- | --- | --- |
| `erp-sso` | ERP 后端 → 主项目 | 一次性 Code 兑换 | 主项目保存 Secret 哈希；仅授予 `sso.exchange`；ERP 保存一次明文 Secret |
| `erp-main-api` | ERP 后端 → 主项目 | team scope、permissionVersion、专利业务 API | 主项目保存 Secret 哈希并授予 5 项最小权限；ERP保存一次明文 Secret |
| `main-permission-center` | 主项目权限中心 → ERP | 拉取 ERP Manifest | 主项目出站配置与 ERP 入站校验配置使用同一对值；不要创建为主项目入站哈希 Client |
| `main-provisioning` | 主项目账号绑定 → ERP | Employee 幂等建档 | 主项目出站配置与 ERP 入站校验配置使用同一对值；不要创建为主项目入站哈希 Client |

四套 ID 和四套 Secret 必须互不相同，不得与浏览器用户 Token、ERP 会话 Secret 或旧 JWT Secret 共用。

`erp-main-api` 最小权限：

```text
team-scope.read
permission-version.read
ip.patent_query.execute
ip.patent_fee.read
ip.patent.read
```

后台任务限制：

```text
metadata.allowedJobNames = ["patent-anomaly-scan"]
```

固定 Header：

| 通道 | Client ID Header | Client Secret Header |
| --- | --- | --- |
| SSO exchange | `X-ERP-Client-Id` | `X-ERP-Client-Secret` |
| 主项目业务 API | `X-ERP-Service-Id` | `X-ERP-Service-Secret` |
| Manifest | `X-ERP-Manifest-Client-Id` | `X-ERP-Manifest-Client-Secret` |
| Employee 建档 | `X-Main-Provision-Client-Id` | `X-Main-Provision-Client-Secret` |

交付要求：

- 文档只回填 Client ID、授权结果、Secret 指纹或受控交付编号；
- Secret 通过密码库、受控文件或一次性安全渠道交付；
- 如果材料已经生成，应核对现有材料并交付，不要自动轮换；
- 如必须轮换，应先通知 ERP 并安排双端同时切换窗口。

### 4.3 RS256 验签材料

主项目团队需要交付：

- active `kid`；预期值为 `main-20260716-01`，最终以主项目实际配置回执为准；
- active 公钥文件；
- 公钥 SHA-256 指纹；
- 当前 previous key 状态，首次部署建议明确回填“无”；
- 公钥轮换负责人和旧公钥兼容期限。

主项目私钥不得离开主项目受控目录，不得交付给 ERP。

### 4.4 应用入口配置

主项目应用启动器需要配置：

```text
应用名称：ERP
启动地址：https://erp.iptt.top/sso/initiate
固定 callback：https://erp.iptt.top/sso/callback
audience：erp
entryPermissionCode：erp.app.view
```

要求：

- `entryPermissionCode` 固定为 `erp.app.view`，管理员不能改成任意编码；
- 只有拥有 `erp.app.view` 的角色/用户才能看到 ERP 入口；
- callback 必须精确匹配，不允许前端传入任意回调地址；
- 未授权用户即使知道 URL，也必须在服务端被拒绝。

### 4.5 联调账号

首次联调至少提供一个成功账号的 `users.id`，账号必须满足：

- 主项目账号已启用；
- 已授予 `erp.app.view`；
- 已绑定 ERP Employee；
- 可在主项目登录后看到 ERP 按钮；
- 可由账号本人现场完成登录，不需要向 ERP 团队提供密码。

完整验收还应准备：

1. 已绑定 Employee 的成功账号；
2. 尚未创建 Employee 的自动建档账号；
3. self scope 账号；
4. team scope 主管账号及至少一个下属；
5. all scope 账号；
6. 无 `erp.app.view` 的拒绝账号；
7. 禁用、撤权或团队调整账号。

同时指定可执行角色授权、撤权和团队调整的主项目操作人。

## 5. 必须由主项目团队在主项目服务器执行的事项

## 6. 必须由 ERP/运维团队执行的服务器事项

### 6.1 准备独立数据库恢复验证环境

ERP 正式迁移前必须完成“同一备份工件”的恢复 smoke。当前共享生产服务器没有 Docker，推荐使用独立发布/恢复验证主机，避免在同时承载两套系统的服务器上临时安装 Docker。

运维需要提供：

- 可连接 ERP 数据库的隔离发布主机；
- Docker daemon；
- 预拉取并固定 digest 的兼容 MySQL 镜像；
- ERP 独立只读备份账号；
- 权限受控的备份目录；
- 充足磁盘空间；
- 精确 backup receipt 的安全传递方式。

如果必须在共享生产服务器安装 Docker，必须另行审批，不能作为本次默认动作。

### 6.2 安全配置 ERP 环境

ERP 运维将主项目安全交付的材料写入 ERP Secret Store 或 `/etc/erp/erp.env`，不得写入 Git 仓库。

需要补齐：

```text
ERP_SSO_CLIENT_ID
ERP_SSO_CLIENT_SECRET
MAIN_API_CLIENT_ID
MAIN_API_CLIENT_SECRET
ERP_MANIFEST_CLIENT_ID
ERP_MANIFEST_CLIENT_SECRET
ERP_PROVISION_CLIENT_ID
ERP_PROVISION_CLIENT_SECRET
ERP_SSO_ACTIVE_KID
ERP_SSO_ACTIVE_PUBLIC_KEY_PATH
```

推荐把公钥放入 ERP 受控配置目录，并通过绝对路径引用。不得复制主项目私钥。

固定地址：

```text
MAIN_SYSTEM_URL=https://iptt.top
MAIN_SSO_BASE_URL=https://iptt.top
IP_API_BASE_URL=https://iptt.top/api/v1
ERP_SSO_CALLBACK_URL_PRODUCTION=https://erp.iptt.top/sso/callback
```

灰度期配置：

```text
ENABLE_SSO_LOGIN=true
ENABLE_PASSWORD_LOGIN=true
ENABLE_LEGACY_SESSION=true
IP_AUTH_MODE=hybrid
```

灰度期仍保留旧登录和旧会话；完成观察并排空旧会话后，再审批切换为：

```text
ENABLE_SSO_LOGIN=true
ENABLE_PASSWORD_LOGIN=false
ENABLE_LEGACY_SESSION=false
IP_AUTH_MODE=client_credentials
```

### 6.4 ERP 备份、恢复 smoke 和迁移

维护窗口内只针对 ERP 数据库执行：

1. 暂停 ERP 外部写入和 ERP 后台任务；
2. 使用独立只读账号生成全量备份；
3. 生成并保存精确 receipt；
4. 使用 receipt 对应的同一工件在隔离 MySQL 中恢复；
5. 校验表、视图、行数、列、索引、约束、触发器、存储过程和事件；
6. smoke 成功后才允许执行五项幂等迁移：

```text

```

7. 迁移完成后重新执行数据库、Redis 和统一认证生产预检。

本步骤不得连接或修改主项目数据库。

### 6.5 ERP 代码和前端部署

运维需要：

1. 保留生产 `.env`、日志和 6 个未跟踪文件；
2. 切换 ERP 代码到候选 Commit；
