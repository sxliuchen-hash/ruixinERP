## 2. ERP 正式接受的主项目契约

以下内容无需再次讨论，后续实现和验收以主项目回填为准：

1. 主项目应用启动器只使用 `/api/v1/applications/my-access` 返回的 `canLaunch/ssoInitiateUrl`，入口固定先进入 ERP `/sso/initiate`。
2. ERP 先生成并绑定浏览器 `state`；主项目 authorize、callback 和 exchange 必须使用同一 state。
3. 一次性 Code 默认 60 秒、服务端只保存哈希、原子消费；state 不匹配时 Code 也视为已消费。
4. assertion 固定 RS256，issuer 默认 `patent-notice-system`，audience 固定 `erp`，Header 必须包含 active `kid`，每次使用唯一 `jti`。
5. `users.id` 是永久用户标识，assertion `sub` 使用其十进制字符串。
6. 权限只返回 `allowed=true` 项，scope 只允许 Manifest 声明的 `self/team/all`。
7. 人工授权优先级为：用户 deny > 用户 allow > 角色 deny > 角色 allow > 默认拒绝。
8. ERP 只接受 `admin/process/supervisor/agent` 四类主项目角色；client 类角色禁止作为登录用户进入 ERP。
9. supervisor team scope 为本人及全部启用下级子树；失败不得扩大为 `all`。
10. 用户禁用、角色/上级变化、改密、撤权、解绑和退出全部设备等操作递增 `permissionVersion`；普通单设备登出不强制退出 ERP。
11. SSO exchange、business API、Manifest sync、Employee provisioning 使用四套相互独立凭证。
12. 后台任务不得伪造 acting user；`patent-anomaly-scan` 必须同时满足路由白名单、Client job allowlist 和服务权限。
13. 回滚优先使用功能开关软回滚；数据库 down 仅允许在无正式数据且备份恢复已验证的条件下执行。
